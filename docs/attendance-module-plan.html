1. Architectural Strategy — 3-Layer Data Approach

We decouple raw time logs from final payroll calculations using a strict 3-layer data model. Each layer is independently verifiable, hash-verified for tamper detection, and locked once consumed downstream.

LayerTableRoleMutability
1. Raw Ledger time_logs Immutable punch records: IN/OUT with timestamp, source, and optional duplicate-of self-reference. Corrections append new rows — never update existing ones. Immutable
2. Daily Worksheets attendance_sheets Computed daily evaluation: reads time_logs, compares against the employee's scheduled shift, applies grace periods, overtime rules, holiday overrides, and leave blending. Each row has a computation_hash (SHA-256 of all inputs). Re-computable until locked_at is set
3. Period Summaries payroll_period_items Aggregate summaries for a 15-day or 30-day payroll cutoff period. Generated from locked attendance sheets. Feeds the payroll run engine for final net pay computation. Locked once period is approved/paid
Design Principle: Raw data is never overwritten. Corrections create new audit-trailed records. Computed sheets can be regenerated by re-running processDailyAttendance() as long as they haven't been consumed by a payroll period. Once a payroll period is approved, all constituent sheets are permanently locked — requiring full period voidal to make changes.

1.2 Duplicate Punch Throttling

Multiple punches of the same type (IN/IN or OUT/OUT) within a 5-minute window are throttled: the earliest punch is kept as the canonical record. Subsequent duplicate punches are created as database rows but marked with a duplicate_of self-reference pointing to the canonical record. This preserves the full audit trail while ensuring computation uses only one punch per type.

4. Business Rules & Computation Logic

4.1 Shift & Core Tracking Rules

  • No night/graveyard shifts: All standard shifts fall cleanly within a single calendar day.
  • 2-Punch Culture with Auto-Deduction: Employees clock IN once (arrival) and OUT once (departure). The system uses only the earliest IN and latest OUT — no summing of intermediate punch intervals. This is the standard Philippine practice for daily-paid workers.
  • Only IN but no OUT: Treated as "incomplete." If the current time is still within business hours, no sheet is generated (marked as in-progress). If the day is fully closed (past midnight or processed the next day), flagged as absent.
  • Only OUT but no IN: Flagged as an anomaly. Cannot determine worked duration. Warning added to sheet notes.

4.2 Lunch Break Rule

The system automatically subtracts exactly 60 minutes for the unpaid lunch break, provided two conditions are met:

  1. The total raw duration (IN→OUT) is ≥ 5 hours (300 minutes).
  2. The work period actually spans the noon break window (12:00–13:00).

If either condition is not met, lunch deduction is 0.

4.3 Grace Period & Lateness

Scenariolate_minutes
On time or early: time_in ≤ schedule_start0
Late but within grace: total_late ≤ grace_period_minutes0
Exceeds grace + forfeit_grace_period_on_exceed = true (PH standard)Full total_late_minutes (grace forfeited)
Exceeds grace + forfeit_grace_period_on_exceed = falsetotal_late_minutes − grace_period_minutes (only excess)
Late Deduction Formula:
chargeable = min(late_minutes, late_deduction_max_minutes) — capped at 30 minutes per day
deduction = chargeable × late_deduction_per_minute — e.g. 30 × ₱10 = max ₱300/day

Early Bird Rule: Clocking in before the shift start time yields 0 regular hours or OT hours for that early period, unless an approved early OT record exists. The employee is simply marked as on time.

4.4 Undertime, Half-Day & The 3-Hour Block Penalty

Actual Worked MinutesClassificationPay
≥ scheduled shift minutesFull Day100% daily rate
> 240 and < scheduled shiftPartial Day with UndertimeProportional: actual_minutes / scheduled_minutes × daily_rate
= 240 (exactly 4 hours)Half-Day50% daily rate
1–239 (less than 4 hours)Unexcused Absence0% — 3-Hour Block Penalty
0 (no punches)Absent0%

The 3-Hour Rule (key in Philippine payroll): If an employee works less than 4 hours, they fail to complete a half-day block. The system automatically flags the day as an unexcused absence with 0 hours paid, unless an approved leave or undertime slip overrides it. Partially worked rest days are exempt from the 3-hour block — rest day work is paid for actual minutes at the rest day rate with no minimum threshold.

4.5 Overtime Rules

  1. Approval-Driven: Actual extra time spent past the shift end time does not trigger auto-payment. The system cross-references actual stay duration against a supervisor-approved overtime_request record and awards the lower value of the two. Unapproved minutes are discarded.
  2. OT Threshold: Admin can set a minimum threshold (e.g., 60 consecutive minutes) before extra time qualifies as valid OT. Extra time below this threshold is discarded even if an approved request exists.
  3. Rate Selection: The OT rate is determined by the shift_type on the approved overtime request at processing time.

4.8 Leave Integration & Blending

Partial leaves (e.g., 4-hour morning or afternoon) blend with actual hours worked to achieve a full day's base wage:

Leave DurationActual WorkedResult
Full day (paid)Any (including 0)Full day credited, 100% paid. Absence type = approved_leave.
Half-day morningAfternoon ≥ 4 hoursFull day blended (4h leave + 4h+ worked). No half-day flag.
Half-day morningAfternoon < 4 hoursInsufficient. Half-day leave credited only. Worked portion insufficient for half-day block → remainder unpaid.
Half-day afternoonMorning ≥ 4 hoursFull day blended (4h+ worked + 4h leave). No half-day flag.
Half-day afternoonMorning < 4 hoursInsufficient. Same handling as above — 3-hour rule applies to worked portion.
Full day (unpaid)AnyHours credited but daily_wage = 0 for those hours.

4.9 Daily Wage Computation Formula

Regular Pay:
hourly_rate = daily_rate / scheduled_work_hours
regular_pay = hourly_rate × regular_hours

Holiday Adjustment:
If holiday_pay_percent > 100 (worked holiday): regular_pay = regular_pay × (holiday_pay_percent / 100)
If holiday_pay_percent = 100 AND unworked: regular_pay = daily_rate (100% holiday pay)

Overtime Pay:
ot_pay = hourly_rate × ot_rate_applied × (approved_overtime_minutes / 60)

Deductions:
late_deduction = min(late_minutes, 30) × 10
undertime_deduction = hourly_rate × (undertime_minutes / 60)

Total Daily Wage:
daily_wage = regular_pay + ot_pay − late_deduction − undertime_deduction

5. Workflows

5.1 Daily Attendance Flow

Employee punches IN / OUT → Self-service portal writes time_log (source=self_service) → 5-min duplicate throttle check → AttendanceService::processDailyAttendance() runs → Loads: employee_schedule + company_config + OT requests + leave requests + holidays → Computes: late, undertime, OT (lower-of-two), holiday pay, leave blending → Persists attendance_sheet with computation_hash

5.2 Manual Attendance Correction Flow (Approval-Gated)

Staff/admin submits correction via portal → Attendance_correction_request created (status=pending) → Admin/superadmin reviews (superior-only: staff→admin, admin→superadmin) → If APPROVED: creates time_log(s) with source=correction → Re-runs processDailyAttendance() to regenerate sheet → If DENIED: stores denial_reason, notifies requester

Duplicate Prevention: Only one pending correction request per (employee_id, attendance_date, correction_type) is allowed at any time.

5.3 Admin Direct Manual Log Flow (No Approval)

Admin creates time_log with source=manual → Audit log auto-created via Auditable trait → processDailyAttendance() re-runs for that employee+date

Admin manual logs are trusted (admin has authority). Only available to admin and superadmin roles. Staff cannot create manual time_logs.

5.4 Payroll Period Generation Flow

Admin selects cutoff period (1-15 or 16-EOM) → PayrollPeriodService locks all attendance_sheets in range → Creates payroll_period (status=draft) → Generates payroll_period_items per employee (aggregates from sheets) → Admin reviews → approves (status=approved) → Payroll run engine computes final net_pay

Lockdown Rule: Once attendance_sheets have locked_at IS NOT NULL, they cannot be recomputed or edited. To make changes, the superadmin must void the entire payroll period (which unlocks all constituent sheets), make corrections, then regenerate.

5.5 Overtime Approval Flow

Employee requests OT via portal (or admin requests on their behalf) → Overtime_request created (status=pending, shift_type determined by schedule+holiday) → Admin/superadmin reviews → If APPROVED: stores ot_rate snapshot + approved timestamp → Later: processDailyAttendance() cross-references this request (lower-of-two rule)

11. Edge Cases & Error Handling

11.1 Time Log Edge Cases

ScenarioBehavior
Two IN punches within 5 minutesEarliest kept as canonical. Later marked as duplicate_of → canonical. ProcessDailyAttendance uses non-duplicate logs only.
Two OUT punches within 5 minutesSame throttling as above. Earliest OUT kept.
Only IN, no OUT (day still in progress)No attendance sheet generated. "In progress" status shown on portal. Not flagged as absent.
Only IN, no OUT (day closed)Flagged as unexcused absence. Attendance_sheet created with 0 hours, notes = "Missing OUT punch."
Only OUT, no INAnomaly. Sheet created with warning. Cannot determine worked duration — 0 hours credited.
Punch exactly at midnightAssigned to the previous day since no night shifts in the system.
Punch on a rest daySelf-service punch blocked unless pre-approved OT exists. Admin can manually log rest day work.
Punch outside schedule bounds (>18h after start)Flagged as anomaly for admin review. Still logged but sheet marked with warning.

11.2 Computation Edge Cases

ScenarioBehavior
Late exactly at grace period boundary (e.g., 15 minutes late, grace = 15)late_minutes = 0 (within grace).
Late at 16 minutes, grace = 15, forfeit = truelate_minutes = 16 (full forfeiture).
Late at 45 minutes, cap = 30chargeable_late = 30. Deduction = 30 × 10 = ₱300 max.
Holiday on Monday, employee absent FridayCheck Friday (last working day before). If absent without leave on Friday → unworked holiday pay = 0%.
Holiday on Monday, Friday was also a holidayWalk further back to Thursday (last non-holiday working day).
Rest day work, employee works 2 hoursPaid for 2 hours at rest day OT rate (1.30). No 3-hour block penalty on rest days.
OT approved for 3 hours, employee stays 2 hoursLower-of-two rule: approved_overtime_minutes = min(180, 120) = 120 minutes.
OT approved for 1 hour, employee stays 2 hoursapproved_overtime_minutes = min(60, 120) = 60 minutes. Extra 60 minutes discarded.
OT approved but OT < threshold (e.g., 45 min, threshold = 60)approved_overtime_minutes = 0. Must meet minimum consecutive threshold.
Schedule change mid-weekEmployee_schedules.effective_from/effective_to determines which schedule applies for each date. ProcessDailyAttendance uses the most recently effective schedule.
Correction for already-locked sheet (paid payroll period)Blocked. User must request superadmin to void the payroll period first.
Duplicate correction request (same employee, date, type)Blocked at application level. Only one pending correction per (employee_id, attendance_date, correction_type).
Self-approval attemptPolicy blocks: submitter role must be strictly lower than reviewer role.

11.3 Concurrency & Locking

ScenarioBehavior
Two admins approve same correction simultaneouslylockForUpdate() on the correction request row ensures only one succeeds.
Payroll period generation running while sheets are being recomputedPeriod generation locks sheets (locked_at) within a transaction. Any in-flight sheet recomputation fails if locked_at is already set.
Batch process for 200+ employeeschunk(50) processing with per-employee isolation. A failure on one employee does not roll back the entire batch.

12. Refinements from v1

#v1 Issuev2 Resolution
1Late deduction was uncapped (infinite ₱10/min)Cap at 30 minutes. Added late_deduction_max_minutes config. Max daily late penalty = ₱300.
2No approval hierarchy on correctionsSuperior-only chain: staff→admin, admin→superadmin. Self-approval blocked. Role comparison enforced in policy.
3Manual attendance scope unclearStaff: self-only. Admin: anyone in branch. Superadmin: anyone.
4Multiple punch pairs unspecifiedPH standard: single pair. First IN + last OUT only. No interval summing. Gaps = employee responsibility.
5Holiday day-before rule naive (just check previous calendar day)Walk backward to last scheduled working day. Skip rest days, Sundays, and other holidays. Holiday on Monday → check Friday.
6OT rates hardcoded (1.25 only)Moved to company_configurations. Four separate rates: regular (1.25), rest day (1.30), regular holiday (2.60), special holiday (1.30).
7Only one OT field on attendance_sheetsSplit into raw_overtime_minutes + approved_overtime_minutes. Full audit trail of actual stay vs awarded OT.
8Rest days not accounted foris_rest_day + is_rest_day_worked flags. Rest day work exempt from 3-hour penalty. Self-punch blocked on rest days.
9Batch processing order dependency not addressedProcess dates in ascending order. Ensures holiday day-before sheets exist when processing a holiday date.
10Correction table missing requester fieldAdded requested_by (FK→users.id). Separates "whose record" (employee_id) from "who submitted" (requested_by).
11Leave blending not fully specifiedDetailed blending matrix. Half-day morning + worked afternoon ≥ 4hr = full day. Half-day + insufficient worked = partial.
12OT shift_type and rate snapshot missingAdded to overtime_requests. shift_type and ot_rate captured at approval time for audit trail.
13Payroll lockdown ambiguityPermanently locked once consumed. Superadmin voids entire period (unlocking all sheets) to allow corrections. No individual sheet unlocking.
14Rest day partial work penalty ambiguousPaid at rest day rate for actual minutes, no minimum. 3-hour block only applies to scheduled work days.
